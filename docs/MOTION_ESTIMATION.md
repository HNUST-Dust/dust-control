# 前向运动估计维护说明

本实现为高频 LQR14 提供前向速度与积分位移，不改变 LQR 状态和输入的定义。
估计器不控制电机，不推断动作模式，也不直接访问设备。位置是沿机体前向速度的
积分，不是世界坐标 X/Y；自旋平移仍需要独立的世界坐标估计与参考生成。

## 阅读顺序与职责

1. `control/chassis_input_reader.cpp`：可选的 HI91 轴向标定、g→m/s²、重力补偿。
2. `balance/balance_controller.cpp::EstimateBodyMotion`：保留原有轮速/腿运动补偿，
   用 IMU yaw rate 把每侧速度换算到机体中心，构造冻结观测。
3. `estimation/wheel_speed_reliability.*`：仅评估左右观测可靠性，不声称测得滑移率。
4. `estimation/body_motion_estimator.*`：三状态 KF，缺失观测跳过校正。
5. `MotionDiagnostics` → `ChassisObservation` → `ChassisTelemetry`：发布诊断。

实时计算固定维度、无动态内存分配。参数只在构造时校验，控制周期不读取 YAML。
数学 KF 与接触判断分离，后续增加外部速度源或更精确的接触模型时不必改写递推。

## 状态、过程与观测

状态顺序为 `[v, a, b]`，单位分别 m/s、m/s²、m/s²；其中 a=dv/dt，b 为加速度计零偏。
`F=[[1,dt,0],[0,1,0],[0,0,1]]`。

每周期 `G=[dt²/2,dt,0]ᵀ`，`Q=q*G*Gᵀ`，再向 `Q[2,2]` 加 `dt*qb`。
这里 q 是每周期随机增量驱动的方差参数，不是连续白噪声 jerk 谱密度；
qb 是零偏随机游走谱密度。更改采样周期时必须重新验证 q 的含义与调参效果。
默认 q=3000、qb=0.1、轮速观测方差 Rv=10、加速度观测方差 Ra=3，P0=I，x0=0。
这些是待通过日志回放和实机标定的初始参数，不是已验证的最优值。

轮速观测 H=[1,0,0]，加速度观测 H=[0,1,1]。
先预测，再更新有效的新 IMU 样本，再以同一个轮速更新前状态评估两侧残差，
最后至多做一次合并轮速校正。重复使用同一 IMU sequence 不会重复压缩协方差。
协方差采用 Joseph 形式更新并显式对称化。

IMU 缺失/未标定时不构造零加速度观测；轮速全部无效时不构造零残差伪观测。
两路都缺失时仅预测，协方差按模型传播。dt 非有限、非正或超过20ms时保持状态，
报告估计无效；数值失败时复位并报告无效，不将坏数值送入 LQR。

## 左右轮可靠性

左右轮速度已包含安装方向、减速比、pitch/腿转动和伸缩速度补偿。
对于正 yaw 为逆时针、半轮距 d 的当前约定，中心速度观测为：

- `zL = vL + d*yaw_rate`
- `zR = vR - d*yaw_rate`

接触力使用现有估计器输出，并非直接力传感器。接触建立阈值为总重12%，
解除阈值6%，低支撑持续5ms才解除已建立接触。单侧确认离地后不参与
左右一致性比较，也不参与轮速融合。接触未知时允许保守使用轮速，可信度上限0.5。

左右残差 `zL-zR` 超过默认0.4m/s时认为不一致。IMU可用时另外检查
`zi-v_prior`，阈值为 `max(0.4m/s,3*sqrt(Pvv_prior))`。
这是带物理下限的启发式门控，不是严格的NIS卡方检验。

- 无惯性证据且左右不一致：两侧一起降权，不猜哪侧打滑。
- 有惯性证据，只有一侧偏离预测：保留符合预测侧，降低异常侧权重。
- 预测残差超过阈值3倍：该侧本周期拒绝更新。
- 一般不一致：可信度立即降至不超过0.05。
- 恢复一致：可信度以100ms从0恢复到1的斜率增长；刚触地不会立即获得满权重。
- yaw缺失时不比较左右，可信度上限0.5。

这些分数是可靠性权重，不是概率。两侧以分数加权合成一次速度观测，
有效方差 `R_effective=2*Rv/(cL+cR)`：双侧满可信时为Rv，单侧满可信时为2Rv。
两侧共享的yaw/运动学误差不会通过两次独立更新重复计算。

这版对异常采用快速降权、缓慢恢复，尚未估计摩擦系数或真实滑移率。
齿隙、踩球时滚动半径变化、IMU延迟和碰撞也可能触发降权，应结合诊断辨认。

## IMU 加速度接入和适用范围

`config/chassis_params.yaml` 的可选 `motion_estimation` 段给出全部参数；
旧配置省略该段时使用相同默认值。未知键、非法轴、非正/非有限方差以及
接触迟滞阈值倒置均在启动时拒绝。

`forward_acceleration_axis=-1` 默认关闭融合。HI91原始轴和陀螺仪安装映射不能
据现有代码直接推断一致，不能仅为启用功能而猜测轴号。
标定时应验证选定轴及sign确实对应机体前向比力，当前输入转换为：

`a_forward = g * (sign * accel_g[axis] + sin(pitch))`

它要求机体x前向、pitch约定与该重力投影一致。先在多个静态pitch角验证
结果接近零，再用已知方向平移验证符号与尺度，核对轮速、姿态、加速度时间延迟。
原始加速度如需预滤波，应在输入边界实现并显式处理延迟，不能靠加大KF噪声掩盖。

当前转换未补偿IMU安装杆臂，也未估计侧向速度。`a_x` 与机体系dv/dt在旋转时
存在侧向运动耦合，因此默认仅在 `abs(yaw_rate)<=0.5rad/s` 时融合加速度；
超过此范围仍可用陀螺仪校正轮速的左右转动差，但不作惯性绝对残差判定。
该阈值是可配置的适用域保护，不代表阈值内杆臂误差必然可忽略。
高速自旋下的共同打滑识别需要后续补充旋转补偿/外部运动观测。

轮速和IMU无法始终识别双侧等量持续滑移，尤其在近似匀速时；
持续拒绝轮速也会使惯性速度不确定性增长。不能把这一估计器当成无漂移里程计。

## 复位与控制接入

沿用现有 BalanceController::Reset 的生命周期：失能、故障、动作交接等既有调用
会同时重置KF、积分位移、可信度历史及IMU序号。此版没有单独改变动作切换语义，
也没有在原始/滤波速度之间增加模式硬切换。若后续希望正常动作交接保留零偏，
应单独拆分“参考同步”和“估计复位”，并验证所有状态转换。

## 遥测与验收

`ChassisTelemetry.version=9`，重新构建发送端、接收端和桥。
新增估计有效性、是否使用IMU/轮速、加速度/零偏、P对角线、有效Rv、
分侧状态/可信度/预测残差/左右残差。无轮速更新时有效Rv为NaN；
估计或源无效时相应数值为NaN，状态码归零。
状态码：0无有效轮速、1离地、2接触未知、3恢复中、4可信、5不一致、6拒绝。

`tests/chassis/body_motion_estimator.cpp` 覆盖：变化加速度与零偏收敛、
单侧/短时双侧空转、腾空协方差增长、落地恢复、无IMU的保守行为、
重复IMU样本、接触迟滞、非法输入、纯自旋的控制坐标边界、
静态倾斜重力补偿与标定开关。测试禁用Eigen动态分配。
配置与ROS遥测回归分别验证参数拒绝和诊断有效性。

离线测试不代表实机验收。实机应先输出关闭采集正常加减速、换向、自旋和踩球日志，
检查正常运动误拒绝率、异常检测延迟、加速度相位和零偏稳定性，再调参数并闭环验收。

## 阈值标定的完整日志链路

仅记录滤波速度和最终可信度不足以确定阈值。本版另外保留：

| 数据 | 用途 |
| --- | --- |
| 控制sequence、monotonic_ns、dt、missed_releases、queue_drops | 区分信号变化与漏周期/漏样 |
| IMU sequence、样本单调时间、原始三轴accel_g、姿态及角速度 | 检查轴向、符号、重力补偿、重复样本和时间延迟 |
| 前向加速度及有效性、是否新IMU样本 | 判断本次惯性门控是否有真实输入 |
| 左右原始电机rpm、电流、腿角/腿速/腿长与伸缩速度 | 排查齿隙、换向和腿运动补偿误差 |
| 左右中心速度观测、轮速有效性、支撑力及归一化支撑比例 | 重建左右一致性检查 |
| 轮速更新前速度和Pvv、合并轮速、实际Rv、最终v/a/b及P对角线 | 检查预测偏差及滤波响应 |
| 左右残差、门控是否启用、实际gate、残差/gate | 区分异常与适用域外/缺失比较 |
| 接触已知/成立、低支撑计时、可信度、状态和独立证据位 | 调接触迟滞、解除延时和恢复速度 |
| 实际q/qb/Rv/Ra及9项可靠性参数 | 确认当时运行所用参数，而不是依赖事后配置文件 |
| 控制模式、目标速度、轮/关节命令和反馈 | 区分操作者命令、真实加速与空转迹象 |

没有进行的比较会记录有效性false及JSON null，不会伪装成零残差。
独立证据位允许同时记录接触未知、缺少yaw、左右不一致、预测不一致等多个原因。

### 采集话题和文件

主话题 `/dust_control/chassis/telemetry` 保留最新帧发布策略，供界面观察。
新增 `/dust_control/chassis/telemetry_samples` 按出队顺序发布每个控制样本，
只在有订阅者时启用。序列化/ROS发布位于非实时消费者；控制线程不执行磁盘I/O。

该通道使用有界队列及best-effort，不能保证无损。采集器另有有界磁盘写入队列，
记录自身丢样计数。必须检查sequence缺口、源队列丢样、控制漏周期与采集器summary；
源采样通常为1kHz，不代表收到的日志必然是完整1kHz，不能插值后声称捕获了毫秒峰值。
原始JSONL适合后续重新分析，保留全部已收到样本，包括拒绝、恢复、失能和无效状态。

使用已重新构建的version 9消息overlay，先启动采集器，再执行实验：

```bash
cd /home/panpoming/dust-control
# 先source当前安装的ROS与本项目消息overlay。
python3 tools/capture_motion_diagnostics.py \
  --config-directory /home/panpoming/dust-control/config \
  --output .cache/motion-calibration/flat-reverse-01.jsonl \
  --scenario flat_reverse --condition normal \
  --notes '平地；换向；记录电池、载荷、轮胎、地面及实验条件' \
  --duration 30

python3 tools/analyze_motion_diagnostics.py \
  .cache/motion-calibration/flat-reverse-01.jsonl \
  --output-dir .cache/motion-calibration/flat-reverse-01-report \
  --pair-thresholds 0.2 0.3 0.4 0.6 \
  --innovation-floors 0.2 0.3 0.4 0.6
```

采集器只订阅，不使能、不改变控制模式、不修改配置。收到首个兼容样本后即开始窗口，
不要求LQR完整接管、操纵杆居中或估计有效，所以不会把最需要分析的异常阶段筛掉。
输出文件以独占方式创建，避免覆盖旧日志。额外输出：

- `.metadata.json`：实验标签/说明、采集时间、配置文本/SHA256、仓库版本与脏状态。
  文件来源仅为操作者提供的配置目录，不假称已核对正在运行进程；实际滤波/阈值参数
  以有效样本中的参数快照为准。
- `.summary.json`：收样/落盘数量、采集器丢样、无效估计数、模拟样本数及错误。
- `threshold_report.json`：残差分位数、超限比例、低支撑连续区间、参数和质量统计。
- `events.csv`：左右状态/证据/接触/门控切换，保留原始时间戳和sequence。

### 实验分组与选阈值

每次独立记录一种条件，使用 `--scenario` 明确工况，避免把不同速度、自旋方向混为一组：

1. `static_level`、`static_tilt`：确认原始轴向、重力补偿、零偏与静止噪声。
2. `flat_acceleration`、`flat_braking`、`flat_reverse`：覆盖正常加减速和齿隙换向。
3. `spin_cw`、`spin_ccw`：分别覆盖不同自旋速度，检查yaw补偿及惯性门控适用范围。
4. `small_projectile`、`large_projectile`：记录弹丸尺寸、接触侧和大致事件时间。
5. `left_airborne`、`right_airborne`、`landing`：核对接触迟滞、低支撑持续时间和恢复过程。

`--condition normal`表示操作者标注无明显异常的工况，`anomaly`表示包含已知异常实验，
`unlabeled`用于无法判断的记录。实验标签不等于逐帧真实打滑标签；推荐在notes记录
视频编号和事件时间，结合视频/外部运动观测定位真实事件。不能用滤波器自己的
trusted/rejected结果充当真值。

先看normal组的残差p99/p99.9和短时低支撑持续时间，再检查候选阈值对异常事件的覆盖。
分析器统计分布时不排除被拒绝/降权的有效观测，避免“只统计已通过门控的数据”造成偏差。
仅对非模拟normal组输出经验分位数包络，**不会自动修改参数**。
低支撑区间遇到丢样会切断；所得持续时间可能低估完整事件，不能直接当作精确触地时长。

阈值扫描固定使用日志里的prior/Pvv，不会重新运行候选参数下的KF，
因此扫描结果是超限比例而非闭环效果预测。高频样本存在时间相关性，
分位数也不是独立样本意义上的置信界限。最终需跨重复实验、速度和地面条件验证，
同时检查误拒绝、检测延迟与恢复时间；不以单一工况的分位数直接定最终阈值。
