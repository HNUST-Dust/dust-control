# EtherCAT 网关 PDO 布局提案 v0

状态：**候选布局，待评审与 HPM5E31 从站资源验证；不是冻结 ABI**。
周期：1000 us；1～3 块板；RxPDO/TxPDO 以从站视角命名。
依据：[协议讨论稿](ETHERCAT_PROTOCOL_DISCUSSION.md)中的已确认范围。

## 容量建议

每块板 RxPDO **1024 B**（主到从），TxPDO **1536 B**（从到主）。
所有板使用同一布局，YAML 配置实际板数、地址、设备绑定和启用通道；
未使用区清零，不按 YAML 中启用设备的数量改变偏移。
下列容量是设计提案，不代表原 USB 每周期能力，也不是硬件实测保证。

| 内容 | 下行容量/板/周期 | 上行容量/板/周期 |
|---|---|---|
| CAN | 底盘、云台各 16 帧，合计 32 帧 | 四路各 8 帧，合计 32 帧 |
| UART1 | 16 字节 | 16 字节 |
| UART2 | 128 字节 | 128 字节 |
| UART3～6 | 每路 32 字节 | 每路 32 字节 |
| 板载 IMU | 无周期写指令；温控保持固件职责 | 1 个原始采样槽 |
| 状态/诊断 | 公共控制、确认与来源期限 | 公共状态、每总线/串口计数与保护状态 |

CAN 下行是兼容现有两来源各 16 个命令组的接纳容量，不代表 32 帧可在 1 ms 内
通过任意一条 CAN 总线发送完毕。主从都须校验每总线实际负载、白名单及队列空间。
CAN 上行每总线 8 帧/ms 提供独立保底；当前六电机配置的实际频率与突发仍需测量。

UART 分配按原线路速率留出平均余量，但 128 字节 DMA 突发不等于能当周期排空；
必须核算聚块、排队和设备 3 ms 新鲜度。特别是低速路可能一次聚集多于本周期容量。

## 字段编码

所有多字节整数显式小端编码；`u8/u16/u32/u64` 为无符号整数。
保留字段发送时为零，接收时严格检查协议要求的保留位。
不发送 C++ 内存结构体，不依赖主从编译器对齐。

### 下行公共头（64 B）

| 局部偏移 | 类型 | 字段 |
|---:|---|---|
| 0 | u32 | magic（数值待统一分配） |
| 4 | u16 | ABI major |
| 6 | u16 | ABI minor |
| 8 | u64 | session_id |
| 16 | u64 | expected_boot_id |
| 24 | u32 | exchange_sequence，周期交换序号，不续控制期限 |
| 28 | u32 | control_flags，建会话/授权转发/停止等位定义待冻结 |
| 32 | u32 | configuration_signature，配置一致性校验，不表示安全认证 |
| 36 | u32 | active_source_mask，启动时固定来源集合，不允许删除来源规避超时 |
| 40 | u32 | cycle_time_us，首版必须等于 1000 |
| 44 | u32 | status_request_sequence |
| 48 | u8 | status_target，沿用会话/CAN/UART 查询语义 |
| 49 | u8 | status_channel |
| 50 | byte[14] | reserved |

主机必须回显刚读到的 boot_id；从站重启后旧 PDO 不匹配而拒绝。
新会话仅在失能状态经明确握手接纳，不以“出现陌生 session_id”自动授权。
停止和新授权请求须定义新事件身份/边沿；重复周期影像不能反复触发授权。

### 每控制来源（272 B）

| 局部偏移 | 类型 | 字段 |
|---:|---|---|
| 0 | u32 | source_sequence，仅业务新目标推进 |
| 4 | u32 | remaining_valid_us，主站扣除目标等待时间后的剩余寿命 |
| 8 | u16 | flags，含批次有效位 |
| 10 | u8 | frame_count，0～16 |
| 11 | u8 | source_id，底盘/云台，必须与固定分区一致 |
| 12 | u32 | reserved |
| 16 | 16 × CAN record | CAN 指令数组 |

每条 CAN record 为 16 B：channel:u8、length:u8、flags:u8、reserved:u8、
id:u32、data:byte[8]。经典 CAN DLC 0～8，标志与 ID 能力按从站声明检查；
默认固件白名单仍决定可发地址，不能仅因字段能表达扩展 ID 就认定已支持。

同来源序号的寿命字段允许随主机等待减少，但载荷及批次标志必须不变；
从站只在首次接纳新序号时建立截止时间，同序号绝不延长期限。
若同序号收到更短寿命，可以收紧期限，具体换算须避免把首次截止时间再次减去等待时间。
空批次保持原有来源活性语义，不重发前次 CAN。
DM 等动作仍在原始 CAN 中表达，不能由主站周期线程因影像重复而重复派发。

### 上行公共头（64 B）

| 局部偏移 | 类型 | 字段 |
|---:|---|---|
| 0 | u32 | magic |
| 4 | u16 | ABI major |
| 6 | u16 | ABI minor |
| 8 | u64 | boot_id，每次复位更新，不允许静默复用 |
| 16 | u64 | accepted_session_id，未接纳为 0 |
| 24 | u32 | publish_sequence |
| 28 | u32 | slave_now_us，用于同影像采样年龄计算 |
| 32 | u32 | configuration_signature |
| 36 | u32 | capability_mask，位定义待冻结 |
| 40 | u32 | business_state，失能/就绪/转发/保护等数值待冻结 |
| 44 | u32 | fault_flags |
| 48 | u32 | accepted_chassis_sequence |
| 52 | u32 | accepted_gimbal_sequence |
| 56 | u32 | status_reply_sequence |
| 60 | u32 | reserved |

来源序号回显仅表示批次已接纳，不代表 CAN 已送达或电机已执行。
业务转发许可与实际电机输出门控分离：允许转发安全失能帧，不等于允许输出力矩。

### 每 CAN 总线上行（208 B）

16 B 头：batch_sequence:u32、cumulative_drops:u32、frame_count:u16、
flags:u16、reserved:u32；随后 8 条 24 B 记录。

24 B 记录：id:u32、bus_sequence:u32、capture_time_us:u32、length:u8、
flags:u8、reserved:u16、data:byte[8]。通道由分区确定。

按采集顺序发布最新可用的有界窗口，不等待主机确认；溢出丢旧并计数。
重复 batch_sequence 不重复解析。新 batch_sequence 允许 frame_count=0，表示新发布的空批次，
不能刷新任何电机时间。截断/溢出不是完整反馈快照；每台电机独立维护最后真实采样。

### 每路 UART（16 B 头 + 独立载荷）

两个方向都采用：block_sequence:u32、peer_ack_sequence:u32、capture_time_us:u32、
length:u16、flags:u16。flags 包含 data_valid、ack_valid、discontinuity；位号待冻结。
下行 capture_time_us 首版保留为 0；主机过期判定继续使用主机生成时间，不比较两端绝对时钟。

**交付提案（待确认）**：双向各路使用最多 4 块在途的累计确认窗口，避免停等确认限制 UART2 吞吐。
块大小分别最多 16/128/32/32/32/32 B；ACK 只确认连续接纳的块。
ACK 字段可在不改变本端 block_sequence 的情况下推进，去重只针对块载荷。

- 只接纳期望的下一块且缓冲有空间时推进 ACK；重复块只回 ACK，不再次解析或写串口。
- 丢失中间块时先不交付后续块，发送端以有界 Go-Back-N 方式恢复；不能无限缓存乱序块。
- 接收端须为首次接纳的块预留完整容量，窗口和 ACK 不能把慢串口挤成无界队列。
- 4 块是候选窗口，持续吞吐还依赖 ACK 延迟、重传和驱动排空速率；不是满载保证。
- 无确认可永久阻塞的情形必须有超时；上行溢出/超龄时显式重置该通道流状态并通知主机断流，
  下行已部分发送的消息不能被新消息覆盖。重置握手、超时值与消息取消规则待单独冻结。
- UART 流量及重传不得刷新 CAN 控制来源期限。

UART 的可靠性交付是新增的 EtherCAT 适配机制，不宣称复制原 USB 上报队列语义；
若评审决定上行也采用不重传，应重新评估并删去对应确认窗口。

### 板载 IMU（48 B）

sample_sequence:u32、capture_time_us:u32、flags:u32、temperature_c:f32、
spi_bytes:byte[25]、reserved:byte[7]。浮点为 IEEE754 binary32，小端，
保留原 USB 25 字节原始样本与温度；无效样本清除有效位，不能用重复样本刷新年龄。

### 诊断（224 B）

- 32 B 会话摘要：8 个 u32，依次为停止原因、拒绝计数、CAN 丢帧计数、
  UART 丢块计数、保护提交错误计数、配置错误计数、固件状态标志、reserved。
- 4 × 32 B CAN 诊断：每路 8 个 u32，依次为 RX 帧数、TX 接纳数、TX 完成数、
  丢弃数、错误数、队列深度、控制器状态、错误计数打包值（TX/RX 各 u16）。
- 6 × 8 B UART 摘要：每路 RX 丢块数:u32、TX 错误数:u32。
- 16 B 状态查询回复：result:i32、value0:u32、value1:u32、value2:u32。
  大于此区的原 USB 详细状态必须通过 CoE 分对象读取或分页；分页规则待冻结，不能静默省字段。

保留完整诊断能力不等于所有原 USB 字段都必须每周期传输。

## 时间语义

slave_now_us 与 capture_time_us 来自同一从站单调时钟，按 u32 差值计算年龄，
差值超出约定有效范围即判无效。周期影像发布时更新时间，保留记录采样时刻。
主机只处理通过 WKC/OP/会话/启动标识校验的新影像，并计入已知周期/传输延迟；
未同步时钟下的单程延迟误差必须通过测量给出上界。DC 首版不作为正确性前提。

## 对象字典组织提案

暂定 RxPDO 映射使用 0x1600 系列、TxPDO 使用 0x1A00 系列，分别由 SM2/SM3 承载；
SM0/SM1 留作邮箱。映射项按上述分区拆分，不把大于 255 bit 的载荷作为一个映射项。
厂商对象优先在 0x2000～0x5FFF 内分配，避免重新解释历史 MPC 对象。

对象索引、subindex、PDO 映射项个数、SM 最大长度、FMMU 与 EEPROM/ESI 模型
须在选定从站协议栈验证后冻结。当前没有可刷写 ESI，不以这份表假称从站已支持。

## 三板线路预算（估算）

每周期三板过程影像总量为 `3 × (1024 + 1536) = 7680 B`。
按输入输出分开映射、100 Mbps、无 VLAN、每帧一个数据 datagram 的保守简单模型，
取每帧有效数据不超过 1400 B，则下行 3072 B 需 3 帧，上行 4608 B 需 4 帧。
每帧按数据之外约 52 B（含前导、帧头、FCS、帧间隙及 EtherCAT 头/WKC）计：
`(7680 + 7 × 52) × 8 / 100000000 ≈ 643.52 us`。

这个数是按输入输出总字节串行化估计的单方向线路占用，不是来回各算一次，
也不是完整周期实测；实际 IgH 切分、LRW 映射、同步报文、从站转发、主机/固件处理
及抖动会改变结果。名义剩余约 356 us 不能直接当作控制计算保证。
相比只估每板 512/1024 B，本提案为原 USB 能力留出更多空间，但三板峰值验收仍是前置条件。

参考：[IgH domain 与多 datagram](https://etherlab.org/download/ethercat/ethercat-1.5.2.pdf)。

## 冻结前的评审点

1. 是否接受每板 1024 B 下行、1536 B 上行与上述通道配额？
2. UART 双向四块窗口机制是否合适；超时、流重置、下行消息取消如何定义？
3. HPM5E31 ESC RAM、SM 三缓冲占用、邮箱、PDO 映射项与固件缓冲资源是否足够？
4. 实测 CAN 反馈、UART DMA 突发和三板主站周期能否满足设备新鲜度？
5. 全部枚举/位号、配置与状态 SDO、错误码、保护参数和握手事件序号需逐项冻结，
   随后才生成 ESI、跨语言向量和主从实现。
